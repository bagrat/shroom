The capture and camera crates in `crates/shroom-capture/Cargo.toml` are MIT, and so is
`cidre`. MIT's one condition is that the notice goes with every copy, so the release and
preview apps now ship `THIRD-PARTY-NOTICES.md` (DECISIONS B123). If the pins ever move,
re-check that the crates at the new rev are still MIT.

**Info:**
- The cookie secret is cached per isolate (`worker.js:416–426`), so a rotation lags.
- The device verifier is compared with `!==` over a SHA-256 hash (`worker.js:1336`). That's not exploitable; the HMAC checks use `crypto.subtle.verify`.
- peek, join and redeem have no rate limit. The codes are ≥96 bits, but unauthenticated requests still cost reads on the owner's account.
- `site.yml:88` runs `npx --yes wrangler@4.145.0` pinned by version, not by lockfile, with `CLOUDFLARE_API_TOKEN` in scope.
- The Cloudflare token sits in plaintext JSON in `~/.shroom`, not the Keychain (mode 700/600, written atomically). This is by design.

**Checked and clean:**
- **Worker:** role checks on every route; mint scoped to `meta/<rec>.json` + `rec/<rec>/`; `/m/` refuses `..`; `.shroom/` is never served; regex-validated IDs; compare-and-swap roster writes; capped request bodies; domain-separated parent proof; Origin-refusing API; `HttpOnly; Secure; SameSite=Lax` cookie; every page interpolation escaped; `frame-ancestors 'none'`.
- **Tauri:** restrictive CSP; `core:default` plus 8 narrow commands; no `{@html}`/`innerHTML`; path-validated `shroom-poster:`; dev flags refused in release builds.
- **Rust:** `sh -c` calls pass values as positional parameters only; `unsafe` is limited to `setsid` and macOS FFI.
- **Installer:** wrapped in `main()`; validated shapes; join link filtered; writes only under `$HOME`.
- **CI:** SHA-pinned actions; no `pull_request_target`; `contents: read` default; inputs passed via `env:`; `persist-credentials: false`; release cert leaf checked.
